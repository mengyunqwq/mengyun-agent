# 界面说明


整个界面就一页：左边是「工作区 / 会话 / 插件」三个可折叠的分区，右边是对话本身。设置、插件市场这些低频的东西收进「设置」浮层，点开才出现，不用来回跳页。顶栏两边只有「标题（中）/ 停止 / 设置（右）」——原右上角的模型显示已经去掉了（它和输入区的模型按钮是重复入口，还把设置往边上挤），模型只住在输入区左下角。

### 接入运营商（在「模型与 API」这一段里）

接入不再是一堆要手填的输入框，而是**先选运营商、再弹窗填 API 信息**：

- 「模型与 API」段最上面是**接入运营商**下拉：列出你存过的每一条（名字 · 运营商 · 模型 · Key 掩码）
- **选一条 = 立刻切过去**（正在用的那条会标「使用中」）
- 下拉末尾两个动作项：**＋ 新建接入…**（弹出表单填地址 / Key / 模型）、**＋ 把当前配置存为一条**
- 弹窗里填完点「保存并切换」：存下来 + 立即生效；**编辑时留空 Key = 不改动已存的 Key**
- 右侧「编辑 / 删除」作用于下拉里选中的那一条
- **Key 只以掩码显示**：界面、截图、旁看都拿不到整串；切换由服务端完成（只有它握有真值）
- 存档文件：配置目录下的 `.mya/api-profiles.json`（与 workspaces.json 并排，可复制迁移）

为什么切换必须走服务端：provider 在构造时就把接口地址、超时、流式这些派生状态算好了，
只改配置字段会出现「界面显示新地址、请求还发到老地方」——所以切换复用的是「保存设置」同一条路。

### 左栏：工作区（文件夹） / 插件

**工作区 = 一个文件夹**，会话挂在它下面——一个文件夹可以有多个会话。
这样分是因为：会话是「在某个项目里干的活」，你找东西时想的是
「我在哪个项目里说过这句话」，而不是「那条对话叫什么名字」。

- 每个工作区一行：文件夹名 + 会话数，点一下**上下展开**它的会话
- 工作区行右侧：**+** 直接在这个文件夹里新建会话（不用再选目录）、**⋯** 更多
  （在这个文件夹新建会话 / 在文件管理器里打开 / 从工作区列表移除）
- 会话行悬停出：**归档**（不删除，收进下面的「已归档」）、**删除**
- 底部「已归档」默认折起来，点开可以**恢复**或删除
- 左上「+」= **新建工作区**：自己选一个文件夹，选完就出现在列表里
- 顶栏「新建会话」还在：选目录的同时就把那个文件夹变成工作区

两个设计细节：

- **会话所在的文件夹一律自动算工作区**——升级之前建的会话不会被藏起来（否则你会以为历史没了）
- **有会话的工作区不允许「移除」**：移除之后会话还在，会立刻把它带回来。
  与其做个假动作，不如直接说清楚（菜单项会置灰并说明原因）

### 左栏：工作区 / 会话 / 插件

学 Codex 的侧栏结构，三个分区各自可折叠（记住你上次收起谁），内容区各自滚动：

- **工作区**：当前会话工作目录的**文件树**——agent 在哪里干活就列哪里；目录点一下展开（懒加载，大目录不卡首屏），右上角 ↻ 重新读取；`node_modules`、`.git` 这类噪音默认隐藏。为什么不做全盘浏览：侧栏一旦能跨出工作目录，它就成了绕过路径约束的入口，而且和 agent 的活动范围对不上
- **会话**：**新建会话**先选工作目录（见 [新建会话](#新建会话先选工作目录)）；点会话切换，悬停出现删除按钮；每个会话下面标着它的**工作目录**；**关掉程序再打开，对话还在**（落盘的历史会话一起列出来，删掉的连文件一起删）
- **插件**：现在装了哪些、开着没有（绿点）。点一行跳进「设置 → 插件管理」，右上「市场」进插件市场。为什么侧栏里不能直接开关：启停插件是低频而且应该先看代码的动作，塞进侧栏会让人随手就点
- 底部的路径就是**工作目录**——agent 读写文件、执行命令都以此为基准
- **重载插件**在「设置 → 插件管理 → 重载」里：往 `plugins/` 目录手动丢了个插件，点一下就能加载，不用重启。侧栏底部原来还有两个常驻按钮（刷新 / 重扫插件），已经去掉了——刷新本来就会自动做，没必要占着位置

### 中栏：对话

对话区的观感对齐 **Codex**，原则是「让回答本身当主角」：

- **配色是中性的**：纯白底 + 一组不带色偏的灰阶，颜色只用来表达状态（成功 / 失败 / 警告），不拿来做装饰。彩色灰（发蓝发紫的那种）盯久了显脏，而这是个要一直开着的界面
- **用户消息**是右侧的一块浅灰气泡，只靠底色区分，不描边
- **并行子任务**在对话流里各占一块（`⚙ 读入口与依赖 · 进行中 · 2 轮 · ↑1.2k`）：运行中默认展开，能看到它最近调了什么工具；跑完自动收起，免得几个任务跑完满屏流水账。状态用颜色说话（排队/进行/完成/失败/中止·超时），子任务花的 token 计入会话累计并单独标出——数字偏小会让人误判成本
- **助手回答**整宽平铺，**没有头像、没有气泡框**。原来每轮都顶着一个方块头像，除了吃掉左边一大截正文宽度，没有任何信息量
- **工具调用**压缩成一行 28px 的灰字：`✓ shell  npm test  1.2s`。状态是 12px 的对勾 / 叉——比实心圆点多给一条信息：不用回忆颜色代表什么，一眼就知道成了还是败了。点一下展开完整输出，再点收起
- **思考过程**同样是一行灰字加一个图标，标题写「已思考 3.2s · 1.2k token」，默认折起来，只有正在思考时图标会慢慢转
- **输入区是一个圆角框**：正文在上面，工具条在框内底部（左边依次是 **+ 号附件**、**权限**、**换模型**，右边累计用量 + **上下文圆环** + 圆形发送键）。把「输入 / 选项 / 发送」收进同一个框里，它们才像一件事。原来那行「Enter 发送 · Shift+Enter 换行」的提示已经去掉——位置让给了附件和权限，快捷键提示属于可以省掉的话

### 权限三档（输入区左下角）

这个开关决定「agent 能不能不问就动手」，所以它常驻显示、用颜色区分，不藏在设置里：

| 档位 | 行为 |
|---|---|
| **询问**（默认） | 写文件、跑命令、危险操作都先问你一句；只读白名单（`ls` / `cat` / `git status` 这类）免问 |
| **工作区内执行** | 工作目录内的写文件和命令免问；**越界仍然问**；`rm -rf /`、`git push --force` 这类硬黑名单任何档位都拦 |
| **完全权限** | 不再询问（硬黑名单除外） |

默认必须是「询问」：它是个一键放开的开关，默认值决定了用户会不会在不知情的情况下让 agent 直接改文件。切换只提交 `approval` 一个字段，模型、地址、密钥都不会被顺手改掉。

### 附件（+ 号）

三种来源：**选择文件** / **选择文件夹** / **选择压缩包**（.zip、.tar.gz 等）。选完把**路径**插进输入框（写成 `@路径`），agent 用自己的工具去读——而不是把内容塞进消息里（大文件塞不下，而且会绕过工具闸门）。压缩包只给路径并提示需要先解压。浏览器模式下拿不到真实路径，会明确说「需要在桌面程序里用」。
- **上下文用量是一个圆环**：平时只有一圈细环（颜色分三档：宽裕 / 需要注意 / 快满了），**鼠标放上去**（或键盘聚焦）才展开具体数字——「上下文 96.0k / 128k（75%）」、窗口大小从哪来、压缩策略，以及「压缩上下文」按钮。为什么要这样：工具条本来就只有一行高，常驻一整行文字会把模型名挤没；用量是状态，平时一眼看出紧不紧张就够了
- **顶栏中间显示当前会话标题**：窗口被别的程序压住一半、或刚切完会话时，不用回左侧列表里找哪条是高亮的
- 正文居中成一个约 800px 的窄列——一行铺满宽屏读起来非常累

其余交互：

- 输入框：**Enter 发送，Shift+Enter 换行**
- 输入框左下角有个**模型按钮**，点一下展开模型面板，不用进设置（见下一节）
- 每一步（每次请求模型）下面会跟一行很轻的用量：`· 第 2 步 · ↑12.0k ↓340 · 2.4s · 累计 12.3k`
- 出错时不只是弹个提示，错误会作为一条消息留在对话里，方便回看
- 顶部「停止」按钮可以中断当前任务（正在跑的工具会被打断，排队中的消息会清掉）
- 同一个会话里连发多条消息会**排队依次执行**，不会两个任务同时改同一个文件

> 卡死的问题单独写了一节：[界面为什么不再卡死](./why-no-freeze.md#界面为什么不再卡死)。

### 新建会话：先选工作目录

点「新建会话」会先让你确认**这次在哪个目录里干活**：

```
┌─ 新建会话 ──────────────────────────────────────┐
│ 选一个工作目录                                   │
│ [ D:\code\my-project            ] [浏览…] [↑]   │
│ 这个目录下的子目录（点一下进去）                 │
│ [src] [tests] [docs] [scripts]                   │
│ 最近用过                                         │
│ [D:\code\my-project] [E:\work\agent]             │
│                        [取消] [用这个目录新建]   │
└──────────────────────────────────────────────────┘
```

为什么要问这一句：**工作目录决定了 agent 能读写哪些文件**（所有工具的路径越界检查都以此为准），而且它会写进系统提示词。默默沿用一个别的项目目录，模型就会去翻错的地方。

- 桌面程序里点 **「浏览…」** 直接开系统原生目录选择框
- 浏览器模式下没有原生对话框，所以做成了「手打路径 + 逐层点子目录」（服务端会把子目录列出来）
- 路径不存在时会明确告诉你是**哪一级**不存在，并提供 **「创建这个目录」**
- 选过的目录会记住，下次直接点「最近用过」
- 会话列表里每个会话下面都标着它的目录——选完不能就看不见了
- 程序启动时自动建的那个会话**不会弹窗**（开机弹窗很烦），用上次的目录

### 上下文窗口：这个数字是从哪来的

用量圆环的分母（模型窗口有多大）过去是**我按模型名猜的**：写死一张 `gpt-4 = 8k`、`deepseek = 128k` 的表。猜错的后果很实际——换到 32k 的模型，环还按 128k 画，看着才 20%，其实早就满了，下一轮直接 400。

现在按这个顺序取值：

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | **你在设置里填的** | `contextWindow` 非 0 就用它，你说了算 |
| 2 | **网关返回的** | Gemini 的 `inputTokenLimit`、OpenRouter 那类的 `context_length` / `max_context_length` / `max_input_tokens`… 这是服务端自己的上限，**权威值** |
| 3 | 按模型名推断 | 上面两个都没有时的兜底，**界面上会标明是推断的** |

拉到之后会缓存到数据目录的 `model-info.json`（按「服务商 + 地址 + 模型名」分开记）。鼠标悬停在那圈用量环上，气泡里会写清楚这个数字的来源：

```
模型窗口 128000 token —— 网关返回的（权威值）
```

推断的会写「按模型名推断的（网关没给这个信息，不准）」——不装懂，你才知道该不该信那个百分比。

> 顺手一个细节：`max_tokens` / `outputTokenLimit` 这类字段**故意不认**。它们说的是「最多输出多少」，拿它当窗口会小得离谱（比如 8k 的输出上限）。

### 每一步花了多少 token

一次请求模型算一步。每一步结束后，对话里会多一行：

```
· 第 2 步 · ↑12.0k ↓340 · 2.4s · 累计 12.3k
```

- `↑` 是这一步的输入（整份上下文），`↓` 是这一步的输出
- `累计` 是本次会话总共烧掉多少（服务商计量的口径，不是估算）
- 数据来自服务商的 `usage` 字段，**每一步单独落盘**——刷新页面后还在，不然「哪一步开始烧钱的」就查不到了，而那正是你要的信息

### 思考过程：像 Codex 那样折起来

接了推理模型（`deepseek-reasoner`、GLM、QwQ 这类）之后，模型会先输出一段思维链再给答案。这段内容**单独成块、可折叠**：

```
┌────────────────────────────────────────────┐
│  [思考] 已思考 · 2.4s · 约 386 token    ⌄  │   ← 点标题栏展开/收起
├────────────────────────────────────────────┤
│ 先看 utils.js 里 humanSize 的实现，         │
│ 它现在只处理到 GB，要加 TB 分支…            │
└────────────────────────────────────────────┘
```

几个细节：

- **思考时自动展开**（不然你不知道它在想什么），**一开始给正文就自动折起**——你这时候要看的是答案
- 折叠状态显示「已思考 · 耗时 · 估算 token 数」
- 思考内容是**用等宽字体、保留换行**显示的，和正文明显区分
- 刷新页面后思考块还在（存在会话历史里）
- **思考内容绝不会被发回给模型**——服务商对历史里的思考字段处理不一致，有的直接报 400。所以它存成内部字段，组装请求时会剥掉

各家放思考内容的字段名不一样（`reasoning_content` / `reasoning` / `thinking`），都认。

终端模式也会打出来，用暗色限行显示：

```
  ┌ 思考过程
  │ 先看 utils.js 里 humanSize 的实现，它现在只处理到 GB…
  └
```

### 上下文用量：一个圆环，放上去才展开

输入区右侧有一个细圆环，显示**这一轮要发出去多少上下文 / 模型窗口多大**：

- 平时只有一圈环，进度就是用量比例（从 12 点方向开始画）
- **鼠标放上去**（或键盘 Tab 聚焦）才展开具体数字，气泡里有四样东西：

```
上下文 18.2k / 128k（14%）· 已折叠 37 条
窗口 128k：网关返回的（权威值） · 本会话累计 96.0k token · 压缩：手动
[ 压缩上下文 ]
```

- 为什么要这样：工具条只有一行高，常驻一整行文字会把模型名挤没；用量属于「状态」，平时一眼看出紧不紧张就够了，真要抠数字再展开。**「压缩上下文」按钮也收进了这个气泡**——只有看用量时才用得上它
- 颜色分档没变：**小于 60% 是主题色，60%~85% 变黄，超过 85% 变红**（档位挂在容器上，圆环跟着变色）
- 分母（窗口大小）的取值顺序是：**你配的 > 网关返回的 > 按模型名推断**（见 [上下文窗口](#上下文窗口这个数字是从哪来的)）
- 分子是**估算值**：中文按 1 字 1 token、英文按 4 字符 1 token 折算。为什么不用服务商返回的真实值——那个只在上一次响应里有，而且压缩之后就对不上了

### 换模型 + 推理等级：输入区左下角就有按钮

换模型是高频操作（便宜的干活、贵的想难题），不该每次都把设置浮层翻出来。所以**输入框左下角**直接放了一个模型按钮：

```
┌────────────────────────────────────────────────┐
│  描述你的需求…（Enter 发送，Shift+Enter 换行）  │
└────────────────────────────────────────────────┘
 [deepseek-flash ●]  Enter 发送 · Shift+Enter 换行
```

点它向上展开模型面板（顶栏不再有模型显示，入口只有输入区这一处）：

```
┌─ 模型 ──────────────────────── [刷新列表] ─┐
│ 当前：deepseek-flash                        │
│ [ 过滤，或直接输入模型名回车切换          ] │
│ ▾ deepseek                            2     │
│    ✓ deepseek-chat                          │
│      deepseek-reasoner                      │
│ ▸ gpt                                 2     │
│ ▸ claude                              1     │
│ ── 推理等级 ──────────────── 当前：中 ──    │
│ [ 默认 ][ 最低 ][ 低 ][ 中 ][ 高 ]          │
│ OpenAI 兼容协议用 reasoning_effort，官方取值 │
│ minimal / low / medium / high。             │
│ 正在向网关拉取可用模型…        [更多设置]   │
└─────────────────────────────────────────────┘
```

- **展开式列表**：模型名按前缀（第一个 `-` `_` `/` `.` `:` 之前那段）分组，每组标题可点开 / 折叠；组多的时候只自动展开含当前模型的那一组。为什么要分组——网关经常一次给上百个模型，平铺成一堵墙根本找不到东西
- 输入框**边打边过滤**：不匹配的行藏起来，命中的组自动展开；直接回车则按输入的名字切换
- **点一下即生效**，不用再按「保存」
- 列表来自网关（同一份 `GET /models`），**带缓存**：下次点开立刻就有内容，超过 10 分钟才在后台静默刷新
- 拉不到列表（不少自建网关没实现 `/models`）会写清原因，并允许**直接手打模型名，回车切换**
- 图像 / 视频 / 向量类模型会标 **非对话**——它们通常不支持工具调用，选了 agent 干活会失败
- `Esc`、点浮层外面、开始发消息都会自动收起

**它只改 `model` 一个字段**：地址、API Key、压缩策略原样保留，不会有意外副作用。

顺带一个容易忽略的细节：**换模型会连上下文窗口一起重算**。用量分母是按模型名推断的（`gpt-4` 是 8k，DeepSeek 是 128k），不重算的话换到小窗口模型后圆环还按 128k 画百分比，看着才 15%，其实早就快满了。

### 推理等级：按三家官方的定义发字段

同一个面板里能调**推理等级**。这里最容易踩的坑是「自己造一套 low/medium/high 直接发出去」——三家官方 API 的参数名和取值**完全不一样**，发错要么被静默忽略（你以为调高了，其实模型还在默认档），要么直接 400 把整轮请求打回来。所以内部只存一组语义值，落到各家时再翻译（翻译只有一份，在 [`src/reasoning.js`](../src/reasoning.js)）：

| 协议 | 官方字段 | 上报的东西 |
|---|---|---|
| OpenAI 兼容（`/chat/completions`） | `reasoning_effort` | 官方取值原样发：`minimal` / `low` / `medium` / `high`（面板上就这五档：默认 + 四个官方值） |
| Anthropic（`/v1/messages`） | `thinking.budget_tokens` | 官方**没有等级概念**，只有 token 预算，所以面板上写清楚实际预算（2k / 8k / 16k）；并且会**自动去掉 temperature**——官方要求开 thinking 时不能自定义它 |
| Google Gemini（`:generateContent`） | `generationConfig.thinkingConfig.thinkingBudget` | token 预算（2048 / 8192 / 24576）；`最低` 在官方语义里就是 `0`（关掉思考） |

- **默认（「默认」那一档）一个字段都不发**，和没有这个功能时完全一样。所以不想折腾就放着，不会因为多了个参数把请求弄坏
- 面板里每一档的悬停说明都会写「实际会发什么字段、什么值」——界面显示的和真正发出去的永远对得上
- 如果老网关不认这些字段（`400 参数不被接受`），错误提示里会直接建议你把它改回「默认」
- 校验在服务端：只接受已知取值，写个 `ultra` 进去会被收敛成「默认」，绝不会把野字段发出去

写进 `config.json` 就一行：

```json
{ "reasoning": { "level": "high" } }
```

### 设置：点开才出现的浮层

顶栏右上角有个 **「设置」按钮**，点一下从右侧滑出设置浮层，再点一下（或按 `Esc`、点面板外面的灰色区域）就收起来。

做成浮层而不是常驻一栏，是因为设置是**低频操作**：常驻会一直占着四百多像素，把对话挤窄。收起来之后页面上只有对话本身。

浮层左边是竖排的六个视图，点谁显示谁：

| 视图 | 干什么 |
|---|---|
| **模型与 API** | 服务商、接口地址、模型、API Key、流式输出、测试连接；GitHub Token |
| **插件管理** | 已装插件的启用 / 禁用 / 卸载、重载、生成插件骨架；下面还有当前可用的工具清单 |
| **插件市场** | 从 GitHub 搜索并安装插件（见下文） |
| **外观** | 浅色 / 深色切换；**主题色色板**（8 个颜色） |
| **行为与安全** | 最大工具调用轮数、免确认放行的工具名单、放开 shell 限制；**上下文窗口与压缩策略** |
| **关于** | 版本与环境信息、目录（可直接打开）、当前生效的完整配置 |

> 快捷键：`Ctrl + ,` 打开/收起设置，`Esc` 关闭。

### 确认闸门：危险操作会停下来问你

模型要写文件或执行命令时，界面会**弹出确认框**，把具体命令摆给你看——**改文件时还会把 diff 摊开**：

```
┌──────────────────────────────────────────────────┐
│  需要你确认                                        │
│  允许执行 edit 吗？                                │
│                                                  │
│      src/session.js                              │
│                                                  │
│  这次改动                                         │
│      src/session.js  +1 行  -1 行                 │
│        const used = estimate(list);              │
│      - this.context.used = estimate;              │
│      + this.context.used = Math.max(est, real);   │
│        return { ...this.context };                │
│                                                  │
│  这是会改动你文件或执行命令的操作。看清楚再决定。     │
│                        [ 拒绝 ]  [ 允许执行 ]      │
└──────────────────────────────────────────────────┘
```

**为什么一定要给 diff**：没有它，你看到的是「写入 src/config.js（1842 字符）」——
等于闭着眼睛点同意。闸门的价值全在「看清楚再决定」，所以：

- diff 由 `src/diff.js` 现算（零依赖的 LCS 行级 diff）：`+` 绿、`-` 红、未改动行留 3 行上下文
- 两万行文件改一行**只显示改动附近**；整段重写会退化成「全删+全加」并说明原因（不硬算、不卡界面）
- 显示上限 80 行，超出会写明「还有 N 行没显示」
- 事后在对话里还能点开「看当时同意了什么」——**同一份 diff**，所以"我当时到底同意了什么"可回溯

其余细节：

- **只读操作（read/glob/grep）不打断你**，直接执行
- **插件工具按插件声明的权限判断**：声明了 `fs:write` / `shell:exec` 这类权限就要问，
  只声明 `fs:read` 的（比如 list_tree）不打断你。权限是**声明不是沙箱**，
  所以装陌生插件前请先看一眼它的代码（加载时也会提醒一句）
- 你拒绝之后，模型会收到「用户拒绝了，不要重试」——**它不会换个写法再来一遍**
- **5 分钟没点，自动按拒绝处理**，不会让会话永久卡住

### 检查点：改崩了能回去

agent 每次动文件之前，都会在你的 git 仓库里记一个检查点（**不碰** HEAD、暂存区、工作区）。
对话里会出现一块：

```
┌────────────────────────────────────────────────────────┐
│  已记录检查点 3f2a91c  1 file changed, 1 insertion(+)    │
│                          [ 看改动 ]  [ 回滚到这一步 ]    │
└────────────────────────────────────────────────────────┘
```

- **看改动**：列出这个检查点改了哪些文件（新增/修改/删除 + 一行统计）
- **回滚到这一步**：先弹确认（会覆盖工作区当前内容，未保存的改动会丢），确认后恢复。
  已知边界：检查点之后**新建**的文件不会被删掉——回滚只恢复检查点里存在的路径
- 不是 git 仓库时什么都不会发生（我们也不会替你 `git init`）；细节见 [checkpoints.md](./checkpoints.md)

### 从别的机器访问（局域网）

默认只监听 `127.0.0.1`，同一网络里的其他机器访问不到——这是有意的最小暴露面。

确实需要时（比如用手机看着它干活）：

```bash
mya web --host 0.0.0.0
```

这时会强制要求一个**访问令牌**，启动时终端会打印可直接打开的链接：

```
局域网访问：http://192.168.1.20:3080/?token=9f3c…
本机访问：  http://127.0.0.1:3080/?token=9f3c…
```

几个要知道的点：

- 用那条带 `?token=` 的链接打开**一次**即可：服务端会种一个 `HttpOnly` cookie 并把地址栏里的
  token 跳掉（免得它留在历史/截图里），之后同一浏览器就不用再粘令牌了
- 脚本/curl 可以走请求头：`x-mya-token: 你的令牌`
- 没带令牌时：页面会**明确告诉你**该用哪条链接打开（以前这里只报「来源不是本机页面」，纯误导）
- **任何拿到这个令牌的人都能操作你的文件**，别在不可信网络里开
