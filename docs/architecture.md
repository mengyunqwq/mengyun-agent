# 工作原理


核心就 40 行，在 `src/agent.js` 的 `run()` 里：

```
        ┌──────────────────────────────────────────┐
        │  1. 组装 messages（系统提示词 + 历史 + 工具描述）│
        └──────────────────┬───────────────────────┘
                           ▼
        ┌──────────────────────────────────────────┐
        │  2. 问模型（流式，边收边推给界面）           │
        └──────────────────┬───────────────────────┘
                           ▼
                  ┌─────────────────┐
                  │ 模型要调工具吗？  │
                  └────┬───────┬────┘
                     是│       │否
                       ▼       ▼
        ┌──────────────────┐  ┌──────────────────┐
        │ 3. 执行工具       │  │ 5. 输出最终答案   │
        │  （同轮可并行）    │  │    保存会话       │
        │  危险操作 → 弹窗   │  └──────────────────┘
        └────────┬─────────┘
                 ▼
        ┌──────────────────────────────────────────┐
        │ 4. 把工具结果塞回 messages，回到第 1 步     │
        │    （最多 maxTurns 轮，防止死循环）         │
        └──────────────────────────────────────────┘
```

**除了这个圈，其他所有文件都是给它打辅助的。**

界面这一层多了一条链路：

```
agent 干活
   │  抛事件（事件总线）
   ▼
SessionManager ──把事件翻译成「界面块」──▶ SSE ──▶ 浏览器渲染
   ▲
   └── 危险操作：挂起，等用户点确认（最多等 5 分钟）
```

几个值得注意的实现细节：

- **消息格式就是标准 OpenAI messages 协议**，没有任何自定义编码。所以界面、终端、以后接微信，都复用同一套。
- **流式工具调用的参数是分片到达的**，需要按 `index` 拼接 `arguments` 字符串再解析。这是最容易写错的地方，`src/provider.js` 的 `SseParser` 处理了它，`test/mock-server.js` 专门把它拆成 3 片来验证。
- **同一轮的多个工具并行执行**（`Promise.allSettled`）。模型经常一口气要读 4 个文件，串行会慢 4 倍。
- **历史裁剪不会留下孤儿 tool 消息**，否则很多服务商直接返回 400。
- **同一会话串行、不同会话并行**：你在一个会话里连发三条消息，它们会排队依次执行。
- **插件目录跟着工作目录走**，不跟着 agent 安装目录走——这条也踩过坑：早期版本写到了程序目录，结果在 A 项目禁用的插件，跑到 B 项目也被禁用。
