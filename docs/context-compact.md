# 上下文压缩


对话长了以后，上下文会撞上模型的窗口上限。撞上的后果不是「变慢」，而是**接口直接报错、会话进行不下去**。

`context-compact` 插件负责在撞上之前把上下文压下来：把**较早的历史**交给模型总结成一段摘要，用摘要替换那一段，**最近几轮原样保留**。

```
↺ 上下文已压缩   已折叠 37 条更早的对话 · 省下约 12.4k token · 当前 18.2k / 128k
```

这条记录会留在对话里（点开能看摘要原文）——**必须显式告诉用户**，否则用量突然掉一半，看起来像 bug。

### 怎么触发：默认自动（留余量），也随时能手动

压缩会**改写对话历史**，所以这件事的取舍是「什么时候动手」：

- **默认自动**：用量超过 **62%** 就压。手动的问题是时机不由程序定、也不由你定——你未必盯着圆环，
  而真撞上窗口的代价是上游直接 400、这一轮白跑。62% 而不是贴边，是为了留出余量。
- **每次压缩都留痕**：对话里会留一条可展开的记录（点开能看摘要原文）。这是自动压缩能被接受的前提——
  历史被改写了，你必须能看出来。
- **也可以手动**：输入框右侧那个**上下文圆环**，鼠标放上去，气泡里就有 **「压缩上下文」** 按钮；
  或者发斜杠命令 `/compact`；`/compact_stats` 看统计（压了几次、最近一次什么时候）。
- **想纯手动**：设置里关掉 **「用完自动压缩」**（`compact.auto: false`）。

| 项 | 默认 | 说明 |
|---|---|---|
| 启用压缩 | 开 | 关掉就只能靠模型的窗口硬扛 |
| 用完自动压缩 | **开** | 关掉就是纯手动：按钮 / `/compact` |
| 自动压缩阈值 | **62%** | 只在自动模式生效；留余量，不贴边才动 |
| 保留最近 | 8 条 | 保留越多越不容易「忘事」，省下的也越少 |

界面上用量气泡会写清当前是哪种模式（「自动压缩已开」/「压缩：手动」），以及这个用量数字
是**上游实测**还是**字符估算**——估算法对中文偏乐观，拿到实测之后就会按实测兜底。

> 你的 `config.json` 里如果显式写了 `compact.auto`，以那份为准（比如老配置里是 `false`，就仍然是手动）。

### 为什么不直接丢掉旧消息

直接截断最省事，但会丢掉关键信息：改过哪些文件、定过什么方案、还有哪些事没做完。模型会在下一轮重新去读一遍文件，甚至改错地方。**总结一次的成本远低于这个代价。**

摘要提示词要求保留五类信息：用户的目标与约束、改过的文件与改动内容、已确认的技术结论、未完成的事项与风险、报错与排查进展。

### 一个容易踩的坑：切点不能乱切

OpenAI 协议里 `tool` 消息必须紧跟着它对应的 `assistant(tool_calls)`。从中间随便切一刀很容易把这一对拆散，服务商直接返回 **400**。

所以真正动手切的是 `Session.compactHistory()`，它会把切点往后挪到安全位置，并在压缩点插入一条 `user` 角色的摘要消息（不用 `system`——部分网关对历史里的额外 system 消息处理不一致）。相关测试专门盯这一点：压缩后不允许出现找不到父级的 `tool` 消息。

### 失败会怎样

**绝不会拖垮对话**：捕获异常、保留原上下文继续跑，同时抛一个 `error` 事件让界面提示出来。不静默是关键——否则用户只会看到「用量一直在涨，压缩好像没生效」却查不到原因。

### 配置

```json
{
  "contextWindow": 0,
  "compact": {
    "enabled": true,
    "auto": false,
    "threshold": 0.75,
    "keepRecent": 8,
    "maxSummaryTokens": 1200
  }
}
```

`contextWindow` 是整个 agent 的配置（用量圆环的分母），`compact` 是压缩策略。也可以用环境变量 `MYA_CONTEXT_WINDOW`，或者插件的 `MYA_PLUGIN_CONTEXT_COMPACT_<KEY>`。

### 自己写一个

这个插件只用了两样东西，是个很好的起点：

```js
ctx.on('messages:before', async (e) => {
  // e.messages  —— 即将发出去的数组，可以原地改
  // e.session   —— 会话对象（measureContext / compactHistory）
  // e.provider  —— 模型客户端，可以自己发请求
  // e.emit      —— 抛事件给界面
});
```

想做「只留最近 N 轮」「按文件路径去重」这类策略，改判断条件即可，不用碰核心代码。
