# 内置工具


| 工具 | 作用 | 默认确认 |
|---|---|---|
| `read` | 读文件，带行号，支持 offset/limit 分段 | 免确认（敏感文件除外，见第 1.5 层） |
| `write` | 写文件（自动建父目录，支持 append） | **要确认** |
| `edit` | 精确字符串替换，要求 old_string 唯一 | **要确认** |
| `glob` | 按通配符找文件，按修改时间排序 | 免确认 |
| `grep` | 正则搜内容，返回 `文件:行号: 内容` | 免确认（敏感文件与忽略目录除外；跑在 worker 里、5 秒超时） |
| `shell` | 执行命令（Windows 走 PowerShell，Linux/macOS 走 sh） | 白名单（只读、不能执行代码/读文件内容）免确认，其他要确认 |
| `web_search` | 联网搜关键词，返回标题 / 链接 / 摘要 | 免确认（只读网络查询） |
| `web_fetch` | 抓一个网页，转成正文文本 | 免确认（只读网络查询） |

后两个要 `web.enabled` 打开才存在（默认开）。**关掉时它们不会出现在模型的能力列表里**——模型是根本不知道有这回事，而不是试了再失败。

### 联网搜索：默认后端为什么是 Bing

`web_search` 需要一个搜索接口。配置项是 `web.provider`，三档可选：

| 取值 | 说明 |
|---|---|
| `bing`（默认） | 免密钥。**实测国内可直连**，100~300ms 返回 |
| `duckduckgo` | 免密钥。但在国内不少网络下**连不通**（实测 12 秒超时后 `ECONNRESET`） |
| `custom` | 自建 SearXNG，或任何返回 JSON 的搜索接口，地址写在 `web.endpoint` |

默认选 Bing 不是偏好问题：DuckDuckGo 在开发这台机器上是**完全连不上**的，而一个「默认后端连不上」的搜索工具等于没有。默认值必须是实测能通的那个。

`custom` 的地址可以写 `{query}` 占位符，不写就自动拼 `?q=`；接口返回 `{"results":[…]}` 或者直接一个数组都能接住。这样你可以接自己的 SearXNG，不必把查询内容发给第三方。

`web_fetch` 只允许 `http:` / `https:`，并且会把 HTML 转成正文（去掉 `<script>`/`<style>`、块级标签转换行、`<li>` 加项目符号、解 HTML 实体），默认截断到 20000 字符——直接返回原始 HTML 会把模型的上下文撑爆。

**看到证书报错怎么读**：如果搜索报 `UNABLE_TO_VERIFY_LEAF_SIGNATURE` 之类，那不是网站挂了，而是有人（公司代理 / 杀软 / VPN）在中间替换证书。正解是设 `NODE_EXTRA_CA_CERTS` 指向公司根证书；`MYA_INSECURE_TLS=1` 能临时跳过校验，但那等于关掉了 HTTPS 的意义，只建议确认风险后短期使用。

几个刻意的设计：

- **edit 不做模糊匹配。** 找不到就报错，并提示你是不是缩进或换行符不一致。模糊匹配「猜着改」是代码被改坏的常见原因。
- **edit 的替换不解释 `$` 模式**：`new_string` 里写 `$$5` 落盘就是 `$$5`（早先两种替换路径行为不同，会静默改错内容）。
- **read 返回带行号的内容**，模型能引用 `文件:行号`，也能精确写 `edit`。
- **路径默认锁在工作目录内**（read/write/edit/glob/grep/shell 全都锁，按真实路径判，junction 也绕不过），要放开就把 `tools.insideOnly` 设成 `false`。
- **grep 优先于 read**，系统提示词里明确要求先 grep 定位再 read，省 token 也省时间。

## 安全机制


一个能读写文件、执行命令、**还能从网上装插件**的 agent，安全设计必须是显式的。这里做了 5 层：

**第 1 层 · 路径限制**
所有文件操作默认只能在工作目录内活动：`read` / `write` / `edit` / `glob` / `grep` / `shell` 的 `cwd`
全部受限，`../../` 会被拒绝。
越界判定按**解析过符号链接的真实路径**做，所以在工作目录里建一个指向 `C:\` 的 junction
也绕不过去（这类绕过实测可利用，所以专门解析真实路径）。
真要让 agent 满盘跑：把 `config.json` 的 `tools.insideOnly` 设成 `false`（显式选择，事后可追溯）。

**第 1.5 层 · 敏感文件**
`.env` / `config.json` / `config.local.json` / 私钥 / `.ssh` / `.aws` 这些默认**不在 glob/grep 的结果里**，
显式 `read` 它们会先问一句（因为 read/glob/grep 平时是免确认的，而这几个文件里装的是密钥）。
关掉这道闸门：`tools.guardSensitive: false`。

**第 2 层 · 确认闸门**
界面弹窗把具体操作摆给你看，你点允许才执行。改文件的工具还会把 **diff** 摊开（`+`/`-` 逐行），
另外事后也能在对话里点开「看当时同意了什么」。高破坏性命令（`rm -rf /`、`git push --force`、`npm publish`、`curl | sh`、fork 炸弹）
**即使开了自动放行也额外再确认一次**。

**第 3 层 · shell 命令分级**
白名单里的命令直接执行，其余要确认。白名单的收录标准是**既不能执行代码、也不能打印文件内容**：

- ✅ 只放：`ls` / `dir` / `pwd` / `cd` / `echo` / `git status` / `git log` / `git branch` / `where` /
  `Get-ChildItem` / `Test-Path` / `node --version` / `npm ls` / `go version` 这类信息量有限的命令
- ❌ 不放：`node`（一个 `-p` 就是任意代码执行）、`find`（`-exec` 能跑命令）、`cat` / `type` / `head` / `tail` /
  `wc` / `Get-Content` / `Select-String`（能读**工作目录之外**的文件内容）、`git show` / `git diff`（会打印文件内容）

命令里一旦出现 `;` `&` `|` `>` `<` `` ` `` `$` 或**换行**，就失去「安全」资格——
`$` 全挡是因为 PowerShell 的 `$env:X` 能直接打印环境变量；换行要挡是因为命令是塞进
`powershell -Command` 执行的，多行会被依次执行（第一行看着像只读，第二行想干什么都行）。

> 这里踩过两个坑：早期实现是先把 `||` 删掉再判断白名单，结果 `ls || rm -rf /` 会被替换成 `ls  rm -rf /`
> 从而骗过检查；以及白名单里曾经放着 `node`，于是「只读查询」实际上是个任意代码执行入口。
> 这两条现在都有测试盯着（`test/selftest.js` 的「安全加固」一组）。

三道权限档位与上面这些的关系（`approval.mode`）：

| 档位 | 命令 | 写文件 | 得到什么 |
|---|---|---|---|
| 询问（默认） | 白名单免问，其余都问 | 都要问 | 每一步都在你眼下 |
| 工作区内 | **不再逐条问**（只拦硬黑名单 + 点名敏感文件） | 落在工作目录里免问 | 少点确认，代价是命令可能碰到工作目录之外 |
| 完全权限 | 只拦硬黑名单 | 免问 | 最快，风险自负 |

> 「工作区内」这一档之所以对命令不逐条问，是因为**命令字符串无法证明它只动工作目录里的东西**
> （`npm test` 会干什么取决于 package.json）。所以这一档的取舍写在明面上：它省的是确认次数，
> 不是安全边界。要每步都过目就用默认的「询问」。

**第 3.5 层 · 子进程环境**
命令拿到的是**白名单环境变量**（PATH / 临时目录 / 语言区域等），不再整体继承 `process.env`——
名字里像密钥的（`*KEY*` / `*TOKEN*` / `*SECRET*` / `*PASSWORD*` …）一律不给，
`npm install` 触发的 postinstall 也一样看不到。

**第 3.8 层 · 正则隔离**
`grep` 的模式有长度上限（500 字符），扫描跑在 worker 线程里、5 秒超时。
正则匹配没有超时机制，`(a+)+$` 这种回溯炸弹打在一行长文本上能把事件循环钉死
（实测 8 秒不出结果，而这个进程同时服务所有会话和 Web/SSE——那不是单个工具失败，是整个 agent 假死）。
超时会被掐掉并如实告诉你「结果不完整」。

**第 4 层 · 插件安装审查**
- 安装前**列出所有文件**，高亮入口文件
- 安装前**静态扫描代码**，标出执行命令、网络请求、碰凭据等敏感操作
- 装完**默认禁用**，你亲自看一眼再手动启用
- 解压时只取插件目录内的文件，**拒绝含 `..` 的路径**（防目录穿越），限制总体积和文件数（防 zip 炸弹）
- 卸载是**移到 `.mya/uninstalled/` 备份**，不是直接删

**第 5 层 · 本地服务来源校验**
网页服务只监听 `127.0.0.1`，并且**校验 Host 和 Origin**。这一步很关键：如果不校验，你浏览器里打开的任何一个恶意网页，都能偷偷向 `127.0.0.1:3080` 发请求来操控这个 agent（CSRF / DNS rebinding，本地服务不设防是很常见的坑）。要暴露到局域网（`--host 0.0.0.0`）时，会强制要求访问令牌。

**还有一条底线原则**：用户拒绝某个操作后，agent 不会换个写法再试一遍。工具返回的是明确的「用户拒绝了，不要重试，请说明原因并询问用户」。

> ⚠️ 老实说：这些机制防的是「模型手滑」和「明显的坏插件」，不是「精心伪装的恶意代码」。插件和 agent 同进程运行，拥有你的全部权限。要跑完全不信任的代码，用 Docker 或虚拟机。
